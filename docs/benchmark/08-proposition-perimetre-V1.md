## 1. Vision et livraisons
Application familiale privée, française d'abord, PC et iPhone, centrée sur menu hebdomadaire. Conserver/transmettre/organiser/cuisiner. P0 = indispensable à la livraison familiale sauf P0 bêta explicitement indiqué ; P1 = amélioration prévue selon charge, P1 bêta = nécessaire avant bêta ; P2 = reporté sans engagement. Les critères P0 et P0/P1 bêta ne peuvent pas être supprimés tacitement. Démarche : nouvelle base modulaire isolée, reprise sélective des règles métier, parseur, formats et ressources autorisées, historique main inchangé. Comparer les options techniques à 12 ; pas de décision framework/SQL/hébergeur dans ce document. Validation utilisateur V2 UX, V3 charte, V4 prototype puis V5/V6/V7 maintenues.

## 3. Report / exclusions
P2 : import URL/JSON-LD, fichiers PDF, liens sociaux et vidéos, plusieurs minuteurs simultanés, propositions automatiques de menus, garde-manger, code-barres, nutrition, commandes vocales, calendrier externe, traduction, collections personnalisées avancées, partage système et édition autonome distribuable/commercialisation (25+ après V8). Le cœur doit être découplé du cloud pour rendre possible cette dernière option, sans promettre édition commerciale maintenant. Hors périmètre initial : réseau social, catalogue public/éditorial, partage public, marketplace/livraison courses, contrôle électroménager, publicité, paiement, conseil médical. Aucun retrait historique proposé.
## 4. Parcours de référence et critères transverses
- Recette → menu → portions → courses → cuisine → minuteur → retour/reprise. Test avec deux recettes et plusieurs occurrences, unités différentes et données manquantes.
- Import texte/photo(s) → brouillon → correction → sauvegarde explicite. Aucun secret client, aucune action privilégiée à partir du contenu importé, aucune quantité/température/allergène inventé silencieusement.
- Deux membres du même foyer modifient sur deux appareils, un hors ligne ; reprise, conflits, aucun écrasement ; un autre foyer et un accès anonyme n'accèdent à aucune donnée privée. RLS si Supabase retenu, fichiers privés, auth et règles de révocation vérifiées.
- Sauvegarde/restauration, corruption, interruption et quota, logout/changement d'identité sans fuite ; préserver les données locales en attente avec avertissement avant purge ; export après épuisement crédits.
- Cibles qualité : WCAG 2.2 AA tous critères applicables, 44 CSS px cible interne fréquente, PC/iPhone réel ; LCP <=2,5 s INP <=200 ms CLS <=0,1 au p75 terrain si données suffisantes, affichage utile <3 s sur profil défini ; jeux synthétiques 100/500 recettes. Aucun défaut bloquant connu, vulnérabilité haute/critique non corrigée ou scénario de perte silencieuse reproductible au jalon. Couvrir parcours essentiels par automatisation si réalisable, justifier exceptions, tests manuels réels. Pas de garantie de données jamais évincées ni alarme arrière-plan.
- IA : cible coût <=0,005 EUR par succès, moyenne <15 s, >=90% imprimés lisibles sans correction (échantillon de référence), aucune erreur critique silencieuse observée dans acceptation ; distinguer taux d'envoi réussi et exactitude. Taux de reprise/abandon et fidélisation cibles exploratoires, pas critères certifiés. Comparatif multi-fournisseurs reporté par D14. Pas de tests payants sans accord.
- Direction visuelle crème/beige/olive et fond olivier si licence vérifiée ; contrastes et lisibilité prioritaires, interface française. Navigation menu, recettes, ajouter, courses, plus = hypothèse V2, pas maquette validée.
